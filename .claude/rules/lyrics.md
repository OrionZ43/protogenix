# Лирика и караоке

Поиск переделан 2026-09-12 после замера на медиатеке Orion (цифры «до» и «после» — `docs/CHANGELOG_CLAUDE.md`). Главное, что было не так: кириллица стиралась при сравнении, формат был лишь добавкой к оценке, длительность не учитывалась, а при отсутствии той же песни показывался текст чужой.

## Конвейер

`KaraokeNotifier` (`karaoke_provider.dart`) слушает `playerProvider` и при смене `currentTrack.id` ищет текст в таком порядке:

1. кэш в памяти (`_cache[trackId]`);
2. `track.lrcPath` из БД — файл, сохранённый при ручном выборе или импорте (`AppPaths.lyricsDir/<trackId>.lrc`), с пометкой масштаба `[pgscale:…]`, если она есть;
3. `LyricsService.findBest(title, artist, filePath, trackDurationMs)` — только «та же песня», иначе «текст не найден».

`LyricsService.fetchLyrics`:
- `.lrc` рядом с аудиофайлом возвращается сразу, со score 999;
- `LyricsMatcher` разбирает название трека на прочтения (`track_query.dart`);
- **этап 1, точные запросы** по основному прочтению: LRCLIB `/api/get` (название, первый артист, длительность), LRCLIB поиск по полям и свободный текст «артисты название» — в LRCLIB, NetEase и Kugou;
- **этап 2, широкие запросы** (до трёх: только название, другие прочтения, части попурри) — только если после этапа 1 нет той же песни с совпавшей длительностью и таймингами (`LyricsMatcher.isGoodEnough`);
- результат — все варианты по порядку выбора; первые с `isConfident` — та же песня.

Каждый запрос к источнику ограничен 12 секундами. Затем `AdvancedLrcParser.parse(content)` → `ParsedLyrics`; активная строка — `AdvancedLrcParser.currentLineIndexFromDuration` (бинарный поиск).

## Выбор (`lyrics_matcher.dart`) — не ослаблять без нового замера

1. **Разбор названий с обеих сторон** (`TrackQueryParser`): скобки, «feat./ft.», «Official Video», «клип», «- Topic», VEVO, номера треков, «Артист - Название», «Название - Артисты», «Название - Remastered 2011». Так же разбираются и найденные записи — на LRCLIB много загрузок с YouTube-заголовками.
2. **«Та же песня»**: сходство названия ≥ 0.8, нет конфликта версий и (артист ≥ 0.5 или длительность ±3 с). Если артист неизвестен (импорт «Unknown») — нужна длительность ±3 с или точное название от 6 символов.
3. **Нет той же песни — «текст не найден»**, а не лучший из чужих. В ручном поиске остальные варианты всё равно видны.
4. **Порядок среди той же песни**: длительность (±3 с → неизвестна → до 15 с → больше или несовместима) → формат (слоги > слова > строки > без таймингов) → оценка. Формат больше не добавка к баллам: из-за этого версия по слогам проигрывала той же песне по строкам.
5. **Версии**: чужой ремикс, live, cover, acoustic, instrumental, 8D, extended или другая скорость — не та песня. Наш live или ремикс против оригинала — штраф −10, тайминги решит длительность.
6. **slowed / sped up / nightcore против оригинала**: `timeScale` = наша длительность / их, если отношение 0.6…1.6. Без длительностей растянуть нельзя — `timingsReliable = false`.
7. **Длительность отличается больше чем на 15 с** — `timingsReliable = false`: караоке показывает текст без синхронизации, импорт такой текст не закрепляет.

Сравнение строк (`lyrics_text.dart`): буквы любого алфавита (`\p{L}`), «ё» = «е», дополнительно в транслите («Kino» = «Кино») и без пробелов («TheWeeknd» = «The Weeknd»); артисты сравниваются по одному. **`\w` в регулярках Dart — только латиница**: для сравнения текста его не использовать.

## `LyricsProvider.search` никогда не бросает исключение

Контракт интерфейса (`lyrics_provider.dart`): при любой ошибке — `return []`. Причина: `LyricsService` ждёт все запросы через `Future.wait` без изоляции ошибок, и одно исключение обнулило бы весь поиск. Новый провайдер обязан оборачивать `search` в `try/catch`.

- Запрос — `LyricsSearchRequest` с режимом: `exact`, `fielded`, `text`. Провайдер объявляет понятные ему режимы в `modes`; остальные ему не отправляются.
- LRCLIB: `/api/get`, `/api/search` по полям и `q`; при перегрузке отвечает 503 (было в замере) — один повтор; записи `instrumental` пропускаются.
- NetEase: только `text`. Текст скачивается лишь для правдоподобных песен из выдачи (`LyricsSearchRequest.relevance` ≥ 0.45, не больше трёх). Повтор — только на 429/503: раньше песня без текста повторялась трижды с паузами. Артисты берутся все, через запятую. Про перехватчик `X-Real-IP` — `dependencies.md`.
- Kugou (с 2026-09-12): только `fielded` — сам собирает строку «артист - название» и передаёт длительность. Свободный текст он не понимает: «The Weeknd Starboy» и «Starboy» дают 0 кандидатов, «The Weeknd - Starboy» — 10 (проверено 2026-09-12). Поэтому запросы по полям несут длительность и `relevance`, а на втором этапе уходят и для других прочтений названия. Качается не больше двух правдоподобных кандидатов. Текст KRC — слова с таймингами — расшифровывается и переводится в YRC (`kugou_krc.dart`: base64 → «krc1» + XOR с известным ключом → zlib; время слов в KRC отсчитывается от начала строки, в YRC — абсолютное), поэтому считается `syllable`. Сильнее всего на западной и китайской музыке; русских песен в проверке 2026-09-12 не нашлось. Совместных артистов пишет через «、» — `splitArtists` это понимает.
- Все три — неофициальные API или открытая база без гарантий. LRCLIB, NetEase и Kugou опрашиваются одним запросом `text`, поэтому новый провайдер с режимом `text` сразу получает те же запросы.

## Форматы

Есть два разных enum, их нельзя путать:
- `LyricsType` (`lyrics_models.dart`) — как текст классифицировал провайдер. Используется при выборе: `syllable`, `enhanced`, `synced`, `plain`.
- `LyricsFormat` (`advanced_lrc_parser.dart`) — что парсер распознал по содержимому: `yrc`, `enhancedLrc`, `syncedLrc`, `plain`.

| `LyricsFormat` | Как выглядит | Тайминги |
|---|---|---|
| `yrc` | YRC от NetEase: `[start,dur](start,dur,0)слог…` | по слогам |
| `enhancedLrc` | `[mm:ss.xx] <mm:ss.xx>слово …` | по словам |
| `syncedLrc` | `[mm:ss.xx] строка` | по строкам |
| `plain` | текст без меток | нет, активная строка не вычисляется |

Формат определяется по содержимому (`detectFormat`), а не по `LyricsType` от провайдера. Парсер покрыт тестами, после любой правки запускать: `flutter test test/features/player/domain/advanced_lrc_parser_test.dart`.

## Растяжение таймингов и пометка `[pgscale:…]` (`lyrics_timing.dart`)

`scaleLyricsTimings` умножает все тайминги (строки, слова, слоги) на `timeScale`. Чтобы выбранный вручную или при импорте текст для slowed-версии после перезапуска открывался с тем же растяжением, в файл первой строкой пишется `[pgscale:1.1398]` (`withScaleTag`), а при чтении она снимается (`readScaleTag`). Текст без таймингов пометку не получает.

## Кэш, дебаунс, токен (`KaraokeNotifier`)

- **Кэш:** `Map<trackId, ParsedLyrics>` в памяти, живёт одну сессию, максимум 50 записей. Вытесняется первый вставленный ключ, то есть это FIFO, хотя в комментарии написано «LRU-lite». **Пустой результат тоже кэшируется**: для трека без текста повторного поиска до перезапуска не будет.
- **Дебаунс 400 мс** (`_kDebounceDuration`): при быстром пролистывании треков запрос не уходит.
- **Load token:** `_scheduleLoad` создаёт новый токен `Object()`, а `_doLoad` сверяет его после **каждого** `await` и выбрасывает результат, если трек успел смениться. Любой новый `await` в `_doLoad` должен сопровождаться проверкой `if (_currentLoadToken != token || !mounted) return;` сразу после него.

## Ручной выбор текста

`lyrics_search_sheet.dart` показывает все варианты; «та же песня» помечена значком. Выбор: `invalidateCache(id)` → `setLyrics(parsed)` (с растяжением `timeScale`) → `LyricsService.saveLrc(content с [pgscale], id)` → `libraryNotifier.updateLrcPath(id, path)`. Путь сохраняется в БД, поэтому при следующем запуске текст берётся из файла (шаг 2 конвейера). Ручной выбор уважается как есть: даже если тайминги от другой версии, текст показывается с синхронизацией.

## Известное — не чинить попутно

- `lyrics_selector_sheet.dart` и `LyricsSelectionLogic` (`lyrics_selection_logic.dart`) — мёртвый код: шторку открывает только `LyricsSelectionLogic.resolveLyrics`, а его никто не вызывает. Её цвета оценки рассчитаны на старую шкалу.
- «Не найдено» кэшируется до конца сессии (см. выше).
- Разбор текста идёт на UI-изоляте (`performance.md`).
