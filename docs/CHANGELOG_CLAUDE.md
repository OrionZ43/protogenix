# Журнал задач Claude

Хронология работы Claude Code в этом репозитории: дата, что сделано, почему, что осознанно не трогал. Новые записи — сверху.

- Правила по темам живут в `.claude/rules/`. Сюда — только история и ссылки на них.
- `.jules/` — журналы уроков Jules (Bolt, Sentinel). Claude их читает, но не пишет туда.

```

**Что:** …
**Почему:** …
**Осознанно не трогал:** …
```

## 2026-09-18 — Импорт альбомов и плейлистов Spotify, честная подсказка про 99 треков

**Что:** Orion: у друга не скачивается плейлист Spotify. Импорт понимал только ссылку на отдельный трек — на плейлист и альбом отвечал «Не страница трека Spotify или нет метаданных».
- `spotify_page.dart`: разбор ссылки (`parseSpotifyLink` — трек, альбом, плейлист; язык в пути, хвост `?si=`, id только base62 — он подставляется в адрес, `security.md`), список треков со встраиваемой страницы `open.spotify.com/embed/…` (`parseSpotifyEmbedCollection`) и число треков из описания обычной страницы (`parseSpotifyCollectionSize`).
- Альбом и плейлист Spotify идут тем же путём, что Яндекс: модели переехали в `importer/domain/import_collection.dart` под нейтральными именами (`ImportTrack`, `ImportCollection`), `_importYandexCollection` → `_importCollection`, `yandex_library_index.dart` → `imported_tracks_index.dart`. Источник в итоге импорта называется сам (`sourceName`), а необычное про него говорит `note`.
- **Плейлист приходит обрезанным: Spotify без входа отдаёт ровно 99 записей** (проверено на плейлисте из 446). Поэтому в шторке импорта под полем ссылки — предупреждение и подчёркнутое «Почему?» с объяснением простыми словами (`showGlassInfo` — новый вариант стеклянного окна с одной кнопкой), а в итоге импорта — «Spotify без входа отдаёт только первые 99 из 446». Число всего запрашивается только когда список упёрся в предел. Для альбома предупреждения нет: альбом приходит целиком.
- `_isSpotify` теперь про любой домен Spotify: непонятная ссылка (исполнитель, подкаст) получает своё сообщение «Подойдёт ссылка на трек, альбом или плейлист», а не «неизвестный формат».
- Попутно: длинный текст в стеклянном окне прокручивается (объяснение не влезало в окно 600 px и ломало вёрстку), плашка импорта показывает 3 строки вместо 2 — итог с новой строкой не обрезается.

**Почему:** полного плейлиста без входа в аккаунт Spotify не отдаёт никому, а вход нам закрыт: расширенную квоту API с 2025-05-15 дают только организациям с 250 000 MAU, Developer Policy запрещает делать из их контента базы и совмещать его с другим сервисом, внутренние точки анонимного токена отвечают 403 «URL Blocked». Решение Orion — не обходить, а честно сказать пользователю. Подробности — `known-issues.md`, раздел про 99 треков.

**Проверено:** `flutter analyze` — 6 (базовый уровень), `flutter test` — 188. Живьём на ссылке друга (`3qDD9XgaWAKwMaQ89uzcIc`): встраиваемая страница → 94 трека и 5 недоступных, всего по описанию 446; альбом «÷ (Deluxe)» — все 16. Импорт прогнан целиком до остановки после первого трека: трек скачался через VISIONOS, лёг в медиатеку с альбомом «Ня» и попал в одноимённый плейлист, итог — «■ Остановлено: 1 из 94, недоступны в самом Spotify: 5, Spotify без входа отдаёт только первые 99 из 446». Подсказка в шторке — виджет-тестом (`importer_sheet_test.dart`): появляется на плейлисте, не появляется на альбоме и треке, «Почему?» открывает объяснение.

**Осознанно не трогал:** вход в аккаунт Spotify и вебвью с прокруткой (см. выше). Обложки у треков Spotify не берутся — в списке встраиваемой страницы их нет, обложка приходит с YouTube, как и раньше. У треков из плейлиста альбомом записывается название плейлиста: своего альбома в этом списке Spotify не отдаёт (`data.md`).

## 2026-09-14 — Перемешивание: название и обложка не от того трека

**Что:** Orion: включил трек, потом перемешивание — играет тот же трек, а название и обложка другие.
- Причина — `just_audio_media_kit` на Windows: mpv физически переставлял плейлист, а индекс текущего трека приходил в перемешанном порядке (`known-issues.md`, «Перемешивание делает приложение»).
- Перемешивание теперь делает `PlayerNotifier`: `player/domain/queue_shuffle.dart` — текущий трек первым, остальные вразброс, выключение возвращает исходный порядок. Очередь перезагружается с той же позиции (`initialPosition` в `setAudioSource`). Режим перемешивания у плеера не включается.
- Новая очередь при включённом перемешивании перемешивается; `playNext` и «Добавить в очередь» кладут трек и в исходный порядок; «Остановить после трека» переезжает вместе с треком.
- Панель «Далее»: переход к треку без перезагрузки очереди (`skipToIndex`).
- Две загрузки очереди сразу (перемешивание во время загрузки медиатеки при запуске) больше не расходятся: у загрузки номер, устаревшая до плеера не доходит.
- Тесты — `queue_shuffle_test.dart`.

**Проверено:**

- вживую на ПК (синтетический клик по кнопке, скрины): установленная 1.2.0 после перемешивания показала «DAMAGE» вместо «Cheat Codes» — баг воспроизведён; новая сборка — «Cheat Codes» через 1, 6 и 12 секунд, выключение тоже без смены трека. ## 2026-09-14 — «Слушать в Protogenix»: трек друга — в свою медиатеку

**Что:** идея Orion — кнопка в статусе Discord не «Слушать на YouTube», а «Слушать в Protogenix»: у кого плеера нет, того ведёт на скачивание, у кого есть — плеер скачивает трек, который слушает друг.
- **Ссылка** `protogenix://listen?v=<id ролика>&t=<название>&a=<исполнитель>&d=<секунды>` (`features/listen/domain/listen_link.dart`). Discord пускает в кнопки только https, поэтому кнопка ведёт на страницу сайта Z43 Studios `/listen?…` с теми же полями, а страница — в приложение по `protogenix://`; там же кнопки скачивания.
- **Приём** (`listen_links.dart`):
  - Windows: установщик прописывает схему в реестр, ссылка приходит аргументом запуска (`main(List<String> args)`). Если плеер уже открыт, второй запуск пересылает её открытому окну и выходит (`release.md`);
  - Android: intent-filter в манифесте; `MainActivity` отдаёт ссылку запуска (`initialLink`) и новые (`onNewIntent` → `open`).
- **Перед скачиванием — вопрос.** Трек уже в медиатеке — «Включить?», нет — «Добавить в медиатеку?». Ролик качается как обычная ссылка YouTube. Трек без ролика (у друга свой файл) ищется на YouTube по названию, исполнителю и длительности тем же строгим подбором, что импорт из Яндекса (`ImporterService.importSearchedTrack`). Всё идёт через очередь импорта.
- Такую ссылку может открыть любой сайт, поэтому разбор строгий и адресов в ссылке нет (`security.md`).
- Страница на сайте — `C:\Project\Z43 Studios`, `src/routes/listen/+page.svelte`, запись в журнале сайта.

**Проверено:**
- тесты разбора (`listen_link_test.dart`);
- вживую на release-сборке: ссылка аргументом запуска; второй запуск с другой ссылкой (переслал её в открытое окно, вышел с кодом 0); запуск по схеме через временный ключ реестра с теми же значениями, что у установщика (ключ потом удалён). Windows при таком запуске отдаёт `protogenix://listen/?…` — разбор это принимает;
- установщик с новой секцией `[Registry]`: Orion поставил тестовую сборку, схема прописалась, «Открыть в Protogenix» со страницы сайта в Firefox открыла вопрос в плеере. Сначала не открылось: был запущен exe прямо из `build\`, а без установщика схемы нет;
- Android собирается; на телефоне не проверено.

**Важно:** кнопка ведёт на сайт — сайт выкладывать раньше релиза плеера (`release.md`). Страница выложена 2026-09-14 (коммит `80ae52e` в репозитории сайта) и отвечает на продакшне.

**Осознанно не трогал:** цвет кнопки в вопросе берётся из палитры в момент прихода ссылки; при запуске по ссылке обложка ещё не разобрана, и кнопка фиолетовая, как и всё приложение в первые секунды.
